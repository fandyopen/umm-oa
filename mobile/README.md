# UMM 移动办公

独立的 **uni-app 标准版 + Vue 2.6** 项目。H5 和微信小程序使用同一套页面、业务接口和权限逻辑，不依赖 PC 的 Vue Router、Ant Design Vue 或 Element UI。现有 PC 页面无需重写。

工作台及底部“消息”页面均提供“通知公告”入口。已登录员工可查看本企业已发布的通知列表、搜索标题并打开正文，发布人和时间与 PC 同步；草稿、撤下通知和其他企业通知不可访问。管理和发布仍在 PC“系统 → 通知公告”完成。

## 本地启动

使用 Node 18 或以上版本、Java 17。先启动现有 `back/start-local.bat` 后端，再执行：

```powershell
cd C:\fandy\project\umm-oa\mobile
npm ci --include=dev
npm run dev:h5
```

首次启动前，须等待依赖安装成功后再运行。若提示 `cross-env` 或 `vue-cli-service` 不是内部或外部命令，说明开发依赖未完整安装；请重新执行 `npm ci --include=dev`，无需全局安装这些工具。若安装日志出现 `ECONNRESET` 或 `ETIMEDOUT`，可临时使用镜像源重试（不修改全局 npm 配置）：

```powershell
npm ci --include=dev --registry=https://registry.npmmirror.com --no-audit --no-fund
npm run dev:h5
```

访问 **http://localhost:3001/mobile/**。手机与电脑在同一局域网时，将 localhost 换成电脑的局域网 IP；允许本机 3001 端口入站。H5 的 `/api` 由开发服务代理到 `127.0.0.1:8080`，手机无需直接访问电脑的 8080 端口。

使用平台已有账号登录。移动端不自带账号、独立用户库或另一套业务数据。PC 与移动端同时登录同一个账号，各自保存登录状态。

## 页面与业务流程

| 入口 | 使用方式 |
| --- | --- |
| 工作台 | 查看企业、当前账号、待办数量和常用应用，进入待我审批、我的发起、已办、抄送。 |
| 应用 | 按已授权模块展示客户与合同、招聘管理、财务与回款、员工自助。未授权模块不会显示；直接访问页面也会检查权限。 |
| 消息 | 分页查看当前账号的待办提醒和抄送通知，进入详情后记录已读。阅读不会替代实际业务办理，也不会自动完成审批。 |
| 我的 | 查看部门、角色、本人考勤、工资和提成入口，切换主题色、退出登录。 |
| 客户档案 | 搜索、分页、查看详情、联系人、跟进记录；按权限新增或修改客户。负责人进入详情新增跟进，填写内容、下次计划和提醒时间，保存时调用平台按钮动作。已启用且发布的流程进入审批；通过后正式写入。 |
| 合同列表 | 查看合同、收费条款、各版本冻结内容与提醒；按权限提交合同审批、登记实际签署日期并签署生效。合同拟定、复杂条款编辑和版本维护仍在 PC 端进行。 |
| 客户风险 | 查看风险原因、客户和关联合同，进入真实业务处理。风险解除仍由跟进、回款、续约等业务条件决定。 |
| 职位管理 | 新增职位 → 提交需求确认 → 审批通过或直接确认后开始招聘；支持职位变更审批、招聘状态调整。 |
| 人才库 | 新增档案 → 登记沟通 → 调整为「沟通中」或「可推荐」→ 进入推荐。查看沟通操作记录、简历版本；联系方式继续受平台权限控制。 |
| 招聘流程 | 推荐可用且未锁定的人才 → 客户反馈 → 有意向后安排面试 → 到时登记面试结果 → Offer 创建、发放、接受 → 上传入职证明并选合同条款确认入职 → 保证期处理或期满结案。列表展示子状态；操作入口使用后端 `availableOperations`，保证期结案时间等限制与 PC 一致。支持推荐撤回、退出、延期、跟进事项和关联替换招聘。 |
| 应收台账 | 查看合同及手工应收余额，从相应节点进入回款登记。 |
| 回款登记 / 开票申请 | 选择已确认应收节点 → 填写日期、金额、凭证等 → 保存草稿 → 从详情提交确认或审批。回款确认后入账；开票审批通过后继续登记实际开票日期、号码和凭证。 |
| 我的考勤 / 工资条 / 提成 | 仅查看本人有权查看的数据。查看工资条后完成原业务的阅读待办。提成展示已批准的核算明细和工资支付状态，提成规则维护、批量核算与工资发放仍由 PC 端办理。 |
| 审批详情 | 从后端重新读取当前账号有权处理的待办，展示申请时冻结的业务内容、附件和历史节点；填写意见后同意或退回。审批通过后的正式写入由已有业务执行器完成。 |

“开启按钮流程设计”本身不会产生审批：必须存在启用且已发布的流程，服务端才会返回 `pendingApproval`；否则按按钮已有执行器直接执行业务。移动端不自行判断流程是否发布，不会先保存正式业务再补发审批。

当前模块中未适配移动办理的历史业务、组织管理、流程设计器和批量财务操作显示提醒或保留在 PC 端处理。抄送列表按现有后端实际数据展示，不额外模拟抄送。消息通过进入页面刷新，当前没有微信订阅推送或后台推送。

## 构建 H5

```powershell
npm run build:h5
```

将 `dist/build/h5` 内容部署到站点 `/mobile/`。页面使用 hash 路由，刷新和从消息直接进入详情无需配置 PC 路由。部署站点需要配置 `/api/` 反向代理到同一套 Java 后端，例如 Nginx：

```nginx
location /mobile/ {
    alias /var/www/umm-mobile/;
    index index.html;
}
location /api/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

登录和业务请求均应使用 HTTPS。无需将 H5 静态页面放进后端鉴权路径中。

## 构建微信小程序

1. 将 `.env.example` 复制为 `.env.production.local`，设置 `VUE_APP_API_BASE=https://实际域名/api`。
2. 填写 `src/manifest.json` 中 `mp-weixin.appid`。
3. 在微信后台配置该域名的 request、uploadFile、downloadFile 合法域名。
4. 执行 `npm run build:mp-weixin`，在微信开发者工具导入 `dist/build/mp-weixin`，进行真机验收后上传。

H5 与小程序共用源码；地址、上传和文件预览通过平台适配处理。当前使用平台账号密码登录，微信手机号授权、微信单点登录、订阅消息尚未开通。未提供真实 AppID 与合法接口域名之前，只能验证编译产物，不能视为已发布的小程序。

当前移动上传入口支持图片凭证；PDF、Word 简历的上传与批量导入使用 PC，已有简历可从移动详情下载。主题色沿用 PC 默认和可选配色，偏好按移动账号在本机保存；不会自动同步另一台设备的外观设置。

## 开发与扩展

- `src/services/catalog.js`：移动应用入口与平台组件标识映射。通过 `/system/module-context` 解析当前模块元数据，不硬编码模块编号，不直接跳转 PC 组件地址。
- `src/services/runtime.js`：登录、会话、请求、模块权限、通用 `submitAction`、上传与下载。流程提交失败重试复用提交标识，连续点击只发一次业务请求。
- `src/services/business.js`：业务表单和现有接口适配。招聘状态标签与可用操作的纯函数直接复用仓库中的 PC 定义，避免维护两套阶段规则；移动构建依赖独立安装在本目录。
- `src/components/Fields.vue`：文本、数字、文本域、可搜索单选/多选、合同关联、日期时间、图片凭证。
- `src/components/ReadOnly.vue`：展示审批字段和冻结的嵌套业务明细。只展示数据，不执行 PC JSX、自定义脚本或动态代码。
- `pages.json`：独立移动页面。后续新增模块需实现对应页面或表单并登记应用入口，模块配置不会自动生成所有移动业务能力。
- 对于新增需要审批的业务按钮，继续配置平台通用业务执行器和已发布的按钮流程，移动页面调用 `submitAction(moduleKey, actionCode, payload)`；不要额外调用一次正式写接口。

后端仅新增 `/mobile/tasks/{kind}`、详情和阅读状态适配；业务接口、审批引擎、账户、角色、数据范围沿用原实现。`mobile.sql` 在既有数据库启动升级时新增 `oa_mobile_message_read` 表，不替换现有业务数据。消息详情和标记已读都会重新校验当前账号的待办可见性。

如果部署环境关闭了自动数据库升级，需要先在现有数据库执行 `back/src/main/resources/mobile.sql`，再启用消息入口。

## 验证

```powershell
npm test
# 先启动 npm run dev:h5，再运行浏览器测试
npm run test:ui
npm run build:h5
npm run build:mp-weixin
```

浏览器测试在 Windows 优先使用已安装的 Edge，其他环境先执行 `npx playwright install chromium`。页面测试使用隔离接口数据，不写入本地真实业务库。Java 测试为 `MobileControllerTest` 和 `MobileIntegrationTest`，使用内存 H2 检查登录、待办访问及阅读状态隔离。
