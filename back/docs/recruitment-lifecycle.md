# 招聘管理

招聘管理包含职位管理、人才库和招聘流程三个子模块。操作步骤位于系统“使用文档 → 模块说明 → 招聘管理”，覆盖需求图片 M04、M05、M06 的功能点。

## 业务闭环

客户领取 / 分配 → 签署服务合同 → 创建职位 → 需求确认 → 人才建档与查重 → 人岗推荐 → 客户反馈 → 多轮面试 → Offer草稿、发放及接受 → 实际入职与凭证 → 按签署条款生成保证期 → 期满结案或离职 / 替换 / 退费事项处理。

- 职位新建、复制、导入均生成独立草稿；已确认需求不能直接覆盖，通过职位变更新增版本。需求确认、变更、合并、转交都接入现有按钮级动作体系，默认不开启审批；仅已发布且启用的设计产生统一待办。
- 申请冻结需求和变更内容，待审时限制编辑。禁止自审批；拒绝和撤回不执行变更。撤回同时取消未完成流程任务及待办，随后可补充资料并重提。
- 同一候选人和职位保持唯一招聘记录；撤回推荐不删除历史。客户反馈有意向后安排多轮面试；面试通过且无未完成轮次后创建Offer，发放后才能登记接受。
- 入职需要实际日期、私有凭证及同客户有效签署合同的收费条款，保证期来自条款；同一候选人不能重复确认有效入职。
- 职位已入职人数、剩余名额、状态，以及客户的合作职位、推荐和入职统计在招聘业务变动后自动重算。达到人数自动完成，保证期退出释放人数后恢复招聘。
- 超期、推荐不足、反馈停滞、入职延期、保证期临近提醒从真实业务条件生成，进入对应记录处理；不会仅凭点击“处理”消除风险。
- 人才支持归属、协作、标签组合检索、个人常用搜索、跟进任务和最近联系时间；任务完成更新联系记录。归属争议指定处理人核实，可保留当前负责人结案，或从争议记录发起转交；转交执行成功后自动结案争议。未结争议不能绕过处理直接转交或合并。候选人合并迁移关联招聘、简历及任务，保留来源档案和审计；同职位流程冲突阻止合并。

## 权限和资料

模块ID为 341300，职位、人才、招聘流程依次为 341301、341302、341303。前端用 component 解析服务端模块上下文，未写死授权ID。按钮默认数据仅首次新增，管理员修改、停用或删除后不在重启时恢复。

业务记录沿用 DataScopeService 的角色数据范围，加负责人 / 协作人 / 流程负责顾问校验。联系方式 contact、简历 preview 和 download 独立授权，列表、详情和导出由服务端脱敏。查看、下载和导出保留日志。导入最多200条且原子提交；导出最多500条，受当前过滤和权限限制。

简历及Offer / 入职凭证保存在 app.recruit-private-dir，默认 back/data/recruit-private，不通过 /profile 或公共下载接口暴露。所有下载经认证和业务归属校验；前端通过带令牌请求获取Blob。PDF / 图片支持在线预览，Word使用下载权限查看。迁移数据库时需另行同步此私有目录。文件包含敏感业务资料，不加入Git。

通知和Offer发放目前为人工办理后的系统登记，不自动向候选人发短信或邮件。退费登记须填写已办理金额并选择私有凭证，系统记录招聘保证期处理依据，不执行资金退款或财务凭证入账。登记替换后，可沿用原职位创建关联替换推荐，依次完成反馈、面试、Offer及实际入职；替换人选入职后自动结案原替换异常，并回写职位和客户统计。进行中的替换不可重复创建，失败后可以重新选择候选人。

## 数据和部署

业务表统一以 oa_recruit_ 为前缀，独立于人员组织表，不会把候选人创建为系统账号。H2在 LocalDatabaseBootstrap 自动运行 recruitment-schema.sql 和 recruitment-menu.sql；菜单采用仅不存在时新增，保留后续管理员配置。

MySQL新库使用 tools/build-mysql-sql.mjs 生成的 db/mysql/umm_oa.sql；已有MySQL库先执行 db/mysql/recruitment-upgrade.sql，再启动后端生成可编辑按钮字典。为业务角色授予所需页面、按钮和数据范围；管理员可直接管理。审批配置在“模块管理 → 对应按钮修改”启用设计并发布。

## 验证

RecruitmentIntegrationTest 使用独立内存数据库，验证完整招聘链、推荐唯一性、保证期退出释放名额、客户统计、按钮审批开关与发布、冻结申请、撤回 / 退回、隐私脱敏、归属权限、私有简历、合并和导入回滚，以及归属争议指定处理人、替换入职自动结案、退费凭证校验、面试时序和冻结任务保护。前端执行构建及针对新增页面的 ESLint 检查。
