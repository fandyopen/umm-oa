# 客户与合同管理

## 页面与导航

一级模块沿用 CRM 模块 ID 和 /crm 路径，更名为“客户与合同管理”。

- 客户档案：客户主档、联系人、公海、分配、跟进、关联商机、关联合同和风险。
- 商机管理：需求、报价、赢单；从客户或商机发起合同，自动带入客户。
- 合同列表：与客户档案、风险提醒同级，统一查找合同并进入详情。详情包含基本信息、收费与回款、审批记录、版本记录、提醒记录。
- 我的待办：通过“合同审批”筛选处理分配给自己的审批任务，核对提交时冻结的合同及收费版本。
- 客户分析：客户经营、合同签约与回款数据。
- 风险提醒：统一汇总客户跟进及合同履约风险，支持客户、合同、风险类型筛选及合同风险处理记录。

合同审批、收费条款、合同版本和合同提醒不再独立显示菜单或列表页签。旧审批链接跳转我的待办，旧收费/版本链接跳转合同列表并保留客户、合同及详情页签，旧提醒链接跳转客户风险提醒。原模块 ID 保留用于按钮授权和历史兼容，不能删除。

## 合同闭环

客户建档 → 商机推进 → 起草合同及收费条款 → 提交审批 → 按已发布流程逐节点审批 → 最终通过/退回 → 签署生效 → 收费到期/回款登记 → 到期续约 → 新合同。

1. 合同必须绑定可访问且已分配负责人的有效客户；客户名称、负责人从主档读取，避免独立维护产生偏差。
2. 起草、退回可编辑；提交前检查合同起止日期、收费合计与合同金额一致。审批人由流程设计的节点配置决定，需具有合同审批权限，不再由经办人手选。
3. 提交人不可审批自己的申请。审批通过后才能签署；退回必须填写意见，修改后重新生成提交版本。
4. 每次提交保存不可覆盖的合同与收费条款快照，通过 workflowRequestId 关联统一审批申请，同时冻结本次流程定义。只有最后一个节点通过才标记合同审批通过；退回重提生成新版本和新实例。生效合同创建新版本后，原签署版本继续决定应收、风险及客户汇总，直到新版本审批并签署。
5. 收费条款支持固定金额、基数比例、收费触发条件、到期日和保证期。回款关联生效条款，不允许超额登记。
6. 客户合同金额、回款、最近回款和合同到期以生效合同为来源自动汇总；历史未关联数据暂保留，首份合同生效后由合同台账接管。
7. 合同到期、收费到期/逾期按合同和收费节点生成稳定提醒 ID，并归属当前客户负责人。风险页与客户详情使用同一来源。
8. 提醒办理必须留下处理记录；真实条件消除后自动关闭，未消除时持续显示，避免“点完成即消失”。
9. 续约复制客户和条款形成独立草稿，保留原合同关联。已生效合同、版本、审批和回款保留审计记录；仅未提交的草稿可删除。

## 数据及权限

采用独立 oa_crm_contract、oa_crm_contract_version、oa_crm_contract_receipt、oa_crm_contract_reminder_log 表，避免被旧“合同与采购”模块清理脚本删除。H2 和 MySQL 共用建表脚本；MySQL 通过生成脚本合并初始化 SQL。

导航合并不合并业务操作权限：审批仍使用 341202/approve，登记回款使用 341203/receive，版本修订使用 341204/edit，提醒处理使用 341205/handle。合同可见范围继承客户归属及部门数据权限，审批人可查看分配给自己的任务及已参与的审批历史。

升级首次运行时，为原收费/版本角色补充合同列表访问，为原审批角色补充我的待办访问，为原提醒角色补充风险提醒访问；不新增提交、签署、回款、审批等动作授权，不改变数据范围。迁移标记 contract_navigation_consolidation_v1 防止后续重启重新授予已撤销的入口权限。新角色需同时授予实际入口及所需业务动作。

## 初始化与验收

### 按钮编码与流程配置

- 在“模块管理 → 按钮修改”选择“合同列表”，搜索“提交审批”，可查看动作编码 submit、权限标识 crm:contract:submit、处理器 crm.contract.submit，在修改页开启流程设计后配置审批，不需重复创建按钮。
- 点击按钮行的“流程设计”，进入“提交审批（submit）”，启用审批并发布。流程只配置在按钮级别，页面默认动作 page 不控制合同提交按钮。
- 未配置或未启用流程时阻止提交，不会直接标记审批通过。角色权限需给审批人授予我的待办入口，以及保留的合同审批模块及审批动作。
- 审批操作统一在待办详情办理。合同详情仅查询审批记录，“查看流程记录”展示各节点、办理人、意见和时间，“版本记录”用于快照追溯和版本对比。
- 既有独立审批的待审合同仅在统一待办的历史任务中保留办结入口；原合同审批接口只接受此类旧任务，新的合同提交及审批统一走通用流程。

### 入口清理

- 删除合同详情中重复的通过、退回按钮及其审批弹窗分支；审批人权限、流程回调、快照和历史记录继续使用。
- 删除旧的手选审批人、独立收费列表和独立合同提醒列表接口；收费及回款在合同详情查询，风险列表统一使用客户风险提醒接口。
- 旧菜单地址仍仅作跳转，避免已有书签失效；隐藏模块编号仍承担审批、回款及提醒处理的独立授权。

### 签署按钮的可选审批

- 签署生效按钮为 341201/sign，自动关联 crm.contract.sign，不需要管理员手填 handlerKey。启动时的一次性迁移只补齐空执行器，不改变名称、权限、启停或流程开关，也不恢复已删除按钮。
- 开启“流程设计”只开放配置入口。未配置、仅保存草稿、流程未发布或审批未启用时，签署仍按原业务规则直接生效；合同内容审批（submit）仍须先完成。
- 发布并启用签署审批后，登记签署日期会生成独立的统一待办。合同在审批期间仍为待签署，界面另显示“签署审批中”；此时不能重复申请或创建新版本。只有所有节点通过后才更新生效版本、应收、客户汇总及风险提醒。
- 签署申请冻结合同版本、实际签署日期、经办人及流程配置。审批人须具有 341202/approve 权限，不能为签署申请人。退回须填写意见，合同不生效，经办人可重新申请；每次申请与历史意见均保留在合同详情“审批记录”中。
- 草稿独立保存，不覆盖已发布流程；重新发布、关闭流程设计或停用新申请，不影响进行中的审批按原快照办结。原签署 API 同样经过统一动作入口，不能绕过已启用的签署审批。

本地 H2 在后端启动时自动创建表和菜单。MySQL 存量库执行 db/mysql/customer-contract-upgrade.sql，随后重启后端生成模块按钮字典并迁移入口权限。在角色权限中为合同负责人授予合同列表、提交及签署，为审批人授予我的待办入口及原合同审批模块的“审批”动作，为财务授予合同列表及原收费条款模块的“登记回款”，为风险处理人授予风险提醒入口及原合同提醒模块的“处理提醒”。

运行 CustomerContractIntegrationTest 和 CrmIntegrationTest 验证客户生命周期、模块结构、审批越权、自审批拦截、版本隔离、收费校验、回款上限及提醒消除。
