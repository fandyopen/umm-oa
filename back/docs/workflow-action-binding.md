# 动作级流程绑定

流程设计按 `moduleId + actionCode` 绑定。业务按钮不再分别创建流程提交接口，而是统一调用：

```http
POST /workflow/action/execute
```

```json
{
  "moduleId": 341001,
  "actionCode": "invite",
  "payload": {
    "nickName": "t1",
    "phonenumber": "13456789098",
    "deptId": 324
  }
}
```

## 执行规则

1. 后端校验当前账号是否拥有 `moduleId + actionCode` 动作权限。
2. 查询 `oa_module_action_flow` 中的动作绑定。
3. 关闭按钮流程设计，或已发布流程的 `approval_enabled = 0` 时，普通动作按原有方式直接执行；合同提交始终要求有效审批流程，关闭后阻止新提交。开启流程设计但尚未发布时阻止执行，避免漏审。
4. 已启用审批时，创建 `oa_workflow_request`，再调用流程引擎生成流程实例和待办。
5. 最终审批通过后，流程引擎调用对应 `WorkflowActionHandler` 执行业务动作。
6. 审批驳回只更新申请状态，不修改业务数据。

## 两种配置入口

原来的模块管理按钮流程设计保持可用。新增入口为：系统 → 审批流程 → 新增审批流程 → 选择所属模块、设计并发布 → 关联按钮；按钮修改页也可以选择该模块已发布的独立流程。两种入口共享发布内容和按钮绑定，历史申请仍使用冻结版本。

`oa_workflow_catalog` 保存独立流程元数据、草稿和版本，发布存入 `oa_process_design`，运行时仍读取 `oa_module_action_flow`。未关联的发布流程不生效。只读权限与设计权限独立，关联必须通过接入校验、租户校验及版本校验。

## 原配置方式

在“系统 -> 模块管理”中维护页面及其按钮动作：

- 动作编码（新增按钮时由系统自动生成）
- 动作名称
- 权限标识
- `handlerKey`
- 执行器 JSON 配置
- 启用状态、排序、说明
- 流程设计开关 `flowDesignEnabled`（可在按钮修改页开启或关闭）

所有按钮统一保存在 `sys_module_action`，取消内置与自定义的编辑限制。默认按钮只在页面首次初始化时补齐；已有名称、权限、排序、说明、状态和流程开关不再被启动同步覆盖。动作编码创建后保持稳定，删除的编码保留身份且不重复使用。

已注册执行器可通过 `GET /workflow/action/handlers` 查询：

- `hr.member.invite`
- `hr.member.transfer`
- `hr.member.dismiss`
- `crm.contract.submit`：仅适用于合同列表的 `submit` 按钮，不能改绑来绕过合同审批。
- `workflow.noop`：只完成流程，不修改业务数据，用于测试

在“系统 -> 模块管理 -> 页面 -> 按钮 -> 修改”中开启流程设计并保存，再进入该按钮的“流程设计”：

1. 从当前模块已有按钮动作中选择“触发动作”，例如“邀请成员（invite）”。
2. 配置审批节点。
3. 保持“启用审批”开启并发布。

动作选择区只读取已开启流程设计的启用按钮。未配置已注册 `handlerKey` 的按钮可用于角色授权，但不能开启流程设计；新增配置数据本身不会自动生成前后端业务操作。

页面级旧绑定与历史保留兼容读取，不再提供页面默认审批选项或接受页面级新发布。旧“流程设置”入口隐藏并跳转到模块管理。成员管理的三个按钮使用：

- `invite`：邀请成员
- `transfer`：调整部门
- `dismiss`：转为离职

## 数据表

- `oa_module_action_flow`：模块动作与已发布流程设计的绑定。
- `oa_workflow_request`：待审批业务申请、审批状态和执行结果。

## 新增业务动作

已有 `handlerKey` 可以复用时，只需要在模块管理树中新增按钮、授权角色并发布流程，
不需要修改 Java。

全新业务操作可以实现一个 `WorkflowActionHandler` 并声明新的 `handlerKey`。之后的
同类动作都可以复用该执行器。业务按钮统一调用 `POST /workflow/action/execute`，
不再需要为每个按钮新增流程提交接口。

## 开关、权限与历史

- flow_design_enabled 控制按钮是否开放流程设计及新申请的审批接入；approval_enabled 是已发布设计的审批执行设置，二者分别保存。
- 关闭设计不会删除流程绑定、流程定义或审批历史，重新开启可继续使用原配置。已发起申请按提交时冻结的定义和执行器处理。
- 模块结构及按钮维护要求模块 340772 的 manage；流程配置要求该模块的 workflow 或 manage。旧模块 340771 的流程管理授权迁移为新入口的流程权限，不自动获得结构管理权限。
- 有审批中申请的按钮禁止删除，可先停用阻止新申请。删除采用保留身份的方式，不复用动作编码。
- 按钮权限标识可以修改；角色授权仍按 moduleId + actionCode 关联，同时下发稳定权限别名供已有业务按钮识别。
- 流程引擎目前支持顺序审批节点；本次调整不增加并行会签、分支路由等未实现能力。
