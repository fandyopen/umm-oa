# 特殊功能：客户数据清理

入口为「系统 → 特殊功能」。仅固定超级管理员可见和调用接口，普通管理员即使拥有角色授权也不能执行。

1. 输入客户 ID 或名称查找；名称支持模糊查询，必须选定一个客户。
2. 点击「预览清理范围」，核对客户 ID、名称、各表删除数量和工资处理说明。
3. 点击「清理关联数据，保留档案」，手动输入客户 ID、完整名称和原因后确认。
4. 系统保存备份，在事务中清理关联，并清零客户主档的业务统计。失败会回滚；数据发生变化时必须重新预览。
5. 显示清理结果后，可点击「彻底删除客户档案」，再次确认后物理删除主档，不受普通删除的客户状态限制。
6. 「清理记录」保留客户信息、原因、操作人、结果和清理前备份，客户删除后仍可查阅。

清理覆盖客户联系人、账户、协作、跟进、有明确客户 ID 的通用业务记录、合同及版本、职位及招聘流程、招聘子记录、应收与财务单据、催收与业务历史、提成归属和分摊，以及对应审批、任务和提醒。流程设计、角色、模块、字典、提成规则、人才主档、简历及其他客户的数据保留。客户主档再次编辑或新增业务后正常恢复相关风险提醒。

共享提成批次只删除本客户的明细与范围，其他客户保留。仍在审批中的关联批次停止原审批。未发放工资项按剩余提成来源重算，取消核对和工资条发布，相关工资批次回到草稿，需要重新核对、审批和发布。已有成功付款（包括部分付款）的工资项保留整项金额和付款事实，只解除客户提成来源；不会撤回实际银行付款。共享批次的既有历史保留。

仅属于该客户且尚未发生成功付款的提成、工资批次，连同明细、历史和工资条通知一起清理，避免留下空批次。已发放记录及包含其他客户数据的批次按上述共享规则保留。

关联识别使用明确外键、业务类型和精确 JSON 字段值；不会按名称或数字片段扫描删除整库。旧商机表没有客户 ID 的记录，仅在合同关联能证明归属且未被其他客户合同共享时清理。

备份存放在后端 `data/customer-cleanup-backups/`，不通过公共上传目录提供、不提交 Git，仅可由超级管理员在清理记录中下载。备份 ZIP 包含待删除及受影响共享记录的 JSON 快照；备份失败不会执行清理。上传文件实体保留，数据库中的客户专属附件关联清理，共享文件不受影响。

入口为“系统 → 特殊功能 → 客户数据清理”。本地 H2 启动会自动创建菜单与清理记录表；已有 MySQL 数据库执行 `back/db/mysql/junk-cleanup-upgrade.sql` 完成两个子页面迁移。清理过程中当前服务的业务写请求及客户风险、人事异动定时写入会互斥执行；服务外直接写数据库不属于该维护入口。

同级“垃圾数据清理”仅扫描构建产物和过期日志。依赖库及依赖缓存不参与扫描和删除，包括 `node_modules`、`.vite`、`.pnpm`、`.yarn`、`.m2`、`.gradle`；构建目录中嵌套的依赖目录也保留。Git 忽略规则用于版本管理，不代表被忽略的文件可以清理；旧页面提交已移除的依赖缓存清理项时会要求重新扫描。
