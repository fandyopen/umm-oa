# 业务模块上下文

适用范围：人事管理、客户档案、商机、合同列表与详情、客户风险、合同历史待办。

## 模块信息从哪里来

业务页面声明稳定的组件标识，不维护数据库数字 ID 或数字 ID 到权限前缀的映射。

1. 详情组件优先使用调用方传入的 moduleMeta。
2. 当前路由的 meta.component 与目标组件标识一致时，使用路由下发的 moduleId 和 perms。
3. 跨模块或上下文缺失时，批量请求 GET /system/module-context?components=...，从当前租户启用的 sys_module 解析真实模块信息。

动态路由保留 component 作为匹配依据。不能仅因有当前路由就把它的 moduleId 用到另一个业务模块。CRM 的组件标识集中在 src/views/eos/crm/moduleContexts.js。

接口返回按组件标识索引的 metadata；未知、停用或其他租户的组件不会出现在结果中。同一租户有多个启用模块指向相同组件时返回业务码 409，要求修正配置，不能任取一项。

该接口只查询 metadata，不授予模块或按钮权限。后端业务接口仍执行原有动作授权校验。/app/user/module/path 返回的是低代码应用 tenantModuleId，不能代替 sys_module 的授权 moduleId。

## 组件约定

withModuleContexts 的首个绑定为组件所属模块，其余是明确的跨模块依赖。绑定维护 component 和中文 label；第二个参数声明各操作方法的 module、action、label。公共 withModuleActionGuards 在调用操作方法前完成检查，同一操作查询期间禁止重复执行，并提供 moduleActionBusy 供按钮显示加载状态。

canModule、canViewModule 只表达已确认的授权；showModuleAction 用于入口展示，避免将未解析误判为无权限。查询成功、权限通过之后，才能打开业务表单或发起业务请求。

- 合同编辑、提交、签署使用合同模块；版本、回款、提醒分别使用各自模块。
- 在客户、商机、风险或待办打开合同详情时，合同动作不能借用来源页面的模块。
- 人事页和组织机构页向 MemberElement 显式传入各自的 moduleMeta。共享成员组件的权限判断和工作流请求使用同一个上下文。
- SActionColumns 支持 moduleMeta；显式传入 null 表示尚未解析。仅已接入操作校验的调用方可设置 allowUnresolved 展示待检查的入口；其他未传属性的既有调用仍使用当前路由。
- 页面初始化静默预加载模块信息，不弹出缺失或失败提示。模块查询使用 silentError，不触发 Axios 的通用错误通知；认证失效仍按原逻辑退出登录。
- 点击时只校验该功能所属的模块：例如“创建新版本暂不可用：合同版本模块未配置或已停用，请联系管理员。”网络失败提示该功能、模块及重试建议。模块配置重复、缺失与无权限分别处理。
- 已确认无权限的按钮继续隐藏；未解析的入口允许点击检查，但不会据此获得权限。检查不通过时不打开表单、不发业务请求，绝不回退到数字常量、0、NaN 或其他模块。
- 再次点击会重试缺失模块或失败请求，无须为临时查询故障刷新整页。一个模块失败不会阻止已解析的其他模块操作。
- 合同列表、客户档案主数据不等待关联模块查询；关联页签单独加载。合同详情自动定位回款、合同入口自动打开新建窗口同样经过具体操作校验。

查询按需批量发出，缓存已解析结果并复用并发请求。登录、注册、会话刷新、切换企业、退出时清空缓存；旧会话的延迟响应不会写入新缓存。业务模块配置变化后刷新页面重新加载。

## 验证及运行

在项目根目录执行 npm run test:module-context、npm run audit:source、npm run build；在 back 执行 Maven test。前端回归直接加载真实 resolver、Vue mixin 和成员动作方法；后端测试使用独立内存库，不操作本地业务数据。

后端新增接口需要构建并重启服务后生效。当前正在运行的 JAR 不会自动更新；使用桌面 start-local.bat 按既有方式重新启动后，再刷新浏览器。
